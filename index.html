Host your repos. Share them peer-to-peer.

GitForest is decentralized P2P git hosting. You host your own repos, share them over a BitTorrent-style DHT network, and collaborate directly with other peers. Seeder and leecher counts are your quality signals — no company controls the network.

Why GitForest

Git is already a decentralized VCS — GitForest just gives it a proper P2P hosting layer.

P2P

True P2P hosting

Repos are announced over a Kademlia DHT and discovered via mDNS on your LAN. Clone and push directly peer-to-peer over the Git protocol — no servers in the middle.

LFS

Decentralized LFS

Large file storage for ML model weights, datasets, and big artifacts. Content-addressed blobs with adaptive chunking and BitTorrent-style piece verification.

CI

Compute marketplace

A decentralized CI/CD system. Submit jobs, or offer your own compute and get paid in crypto — Lightning, Ethereum L2, and Solana backends.

KEY

Identity is a keypair

Your Ed25519 public key is your identity. gitforest init and you're on the network — no accounts, no passwords, no signups.

FORK

Collaboration built in

Signed patches, fork + merge requests, and access control lists — collaboration primitives designed for a network with no central authority.

WEB

Web UI & CLI

Manage repos, blobs, compute jobs, and peers from the local web dashboard at 127.0.0.1:7878 or from the terminal.

Up and running in four commands

No accounts. No hosting bills. Just a keypair and a daemon.

1

Create your identity

gitforest init

Generates an Ed25519 keypair at ~/.config/gitforest/. Your public key is your peer ID.

2

Add a repo

gitforest add ./myrepo

Registers any local git repo to share on the network.

3

Start the daemon

gitforest daemon

Announces your repos on the DHT and starts the Git protocol server for direct P2P clone/push.

4

Clone anywhere

git clone gitforest://<peer_id>/repo

From any other machine running GitForest. That's it.
