Compute Marketplace

GitForest includes a decentralized CI/CD system. Peers offer their compute and get paid in crypto for running builds and tests. No central build farm required.

As a job submitter

1. Create a .gitforest-ci.yml in your repo root:

name: Build and Test
docker_image: rust:1.75
timeout_secs: 600
steps:
  - name: Build
    run: cargo build --release
  - name: Test
    run: cargo test
artifacts:
  - target/release/myapp

2. Submit the job:

$ gitforest compute submit myrepo --max-sats 10000
$ gitforest compute status <job_id>

As a compute worker

1. Make sure Docker is installed and running.

2. Configure your payment wallet:

$ gitforest compute wallet lightning lnbc1your_address...

3. Start offering compute:

$ gitforest compute worker-start --cpu 4 --ram 8192 --rate 1000

4. Restart the daemon — it announces your compute offer on the DHT and jobs start flowing in.

Browse available workers with gitforest compute offers and stop offering with gitforest compute worker-stop.

Supported payment chains

  • Bitcoin Lightning (default) — fast micropayments, no on-chain transaction per job
  • Ethereum L2 — Arbitrum, Optimism, Base, Polygon
  • Solana

Payment backends are pluggable via the PaymentBackend trait. Chain integrations are actively being wired up — today the implementation is a stub for testing the marketplace flow.

Why decentralized CI?

  • No vendor lock-in or per-minute pricing on a central build farm
  • Your compute earns crypto when idle
  • Builds run close to the network — repos and artifacts are already P2P
  • Censorship-resistant: nobody can block your CI pipeline
